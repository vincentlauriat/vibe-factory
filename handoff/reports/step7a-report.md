## Architecture

- **The server API is the only seam (ADR-007).**
  - The app never reads `.vibe/`.
  - `VibeAPI` is UI-free, so the app and the tests share it.
- **Models.**
  - Decoding is hand-written with `CodingKeys` spelled out, and field names follow `events.md` and `api.rs`.
  - `TaskStatus` and `RunStatus` are open enums: an unknown value becomes `.unknown(raw)` and never throws.
  - Phases, gates, subtask statuses, verdicts and severities are `Name`, a string wrapper the app only displays.
  - Roles are `String`, since custom roles exist.
  - The list row and the detail have different `run` shapes:
    - `TaskRow.run` is a `RunSummary` of `{status, current_phase, pending_approval}`;
    - `TaskDetail.run` is the full `RunState`, or null.
  - `number`, `spec` and `plan` can be null.
  - `EvalSuite` keeps the summary as `JSONValue` and exposes typed `rows` (`EvalRow`). Its keys come from `evals/summarize.py`.
- **Events.**
  - `Event` is decoded from the `type` tag. It has one case per documented type, with 0.5 fields defaulting as `events.md` states:
    - `call` defaults to `000000000000`, `model` to `""`, `exit_code` and `output_file` to null, `timed_out` to false, `output_chars` to 0;
    - `run_finished` totals default to zeros, and its date to 1970.
  - An unknown type, or a known type whose fields do not decode, becomes `.unknown(type:payload:)`.
  - `Envelope.schema` defaults to 1.
  - Encoding round-trips.
- **Dates.** The custom parser accepts:
  - `Z` or an offset;
  - no fraction, or 1 to 9 fractional digits, since chrono writes microseconds.

  The encoder writes microseconds in UTC.
- **`VibeClient`.**
  - Based on `URLSession`, with `Authorization: Bearer`.
  - It has a method for every existing route: health, tasks, createTask, task, run(resume:), cancel, approve(comment:), reject(reason:), changes, events(after:all:), evals, and `stream(ref)`.
  - `VibeError` has four cases:
    - `unauthorized` (401);
    - `notFound(message)` (404);
    - `server(status, message)`, where `message` is taken from `{"error": …}`;
    - `transport`.
- **SSE, in three layers.**
  - **`SSEParser`**: byte-by-byte, following the HTML spec:
    - CR, LF and CRLF line ends, including CRLF split across chunks;
    - comments, multi-line `data`, a leading space stripped;
    - `id` kept across events that have none (`agent_delta` has no `id`), and an `id` containing NUL ignored;
    - an event without data is not dispatched;
    - UTF-8 is decoded per line, so a character split across chunks is safe.
  - **`SSEConnection`**: payload-agnostic reconnection with doubling backoff (0.5 s up to 10 s).
    - The caller builds each request from the last event id. That is how the same connection will later serve the global `/api/stream` with `since=`.
    - A 401, a 404 or another 4xx stops it. Network errors, 5xx and a closed body reconnect.
  - **`EventStream`**: the per-task stream.
    - It decodes `Envelope`s.
    - It deduplicates on `(run, seq)`, never on `seq` alone, because `seq` restarts at 1 with each run.
    - Before reconnecting it compares the last run it saw with the current `run.run_id` (`GET /tasks/{ref}`). If a new run started, it asks from `after=0`, so the first events of that run are not skipped.
    - The token goes in the header, not in the URL.
- **`ServerProcess`.**
  - It resolves `vibe` from the setting, then `~/.cargo/bin/vibe`, then `PATH`.
  - It runs `vibe --project <dir> --json serve --bind 127.0.0.1 --port 0 [--evals DIR]` with `Process`, never a shell. `currentDirectoryURL` is the project.
  - The child's `PATH` gets `~/.cargo/bin`, `/opt/homebrew/bin` and `/usr/local/bin` added.
  - Both pipes are drained for the life of the child, with the last 8 KB of stderr kept for error messages.
  - It parses the first stdout line `{"url","port","token"}`, with the human lines of older servers as a fallback. It builds the base URL on `127.0.0.1:<port>`, because the Host check accepts only that form.
  - It then polls `/api/health` until it answers.
  - Stopping:
    - `stop()` sends SIGINT, the server's graceful shutdown: runs are cancelled and stay resumable, and the token file is removed. After the grace period it sends SIGTERM.
    - `interruptAndWait()` is for app quit.
    - `deinit` sends SIGINT.
- **App.**
  - `ProjectSession` (`@Observable`, main actor) owns one connection: a child or a remote server.
    - It has a state: idle, starting, connected, or failed(message).
    - It polls the board every 2 s and posts notifications on board transitions.
  - `SessionRegistry.shared` holds every open session. It feeds the menu bar counts and the quit hook.
  - One `@Observable` view model per screen.
  - Menu commands reach the focused window through `focusedSceneValue(\.project, …)`.

## Decisions and deviations

1. **`--bind 127.0.0.1:<port>` does not exist.** `--bind` takes an address only, and `--port 0` picks a free port. The app therefore runs `--bind 127.0.0.1 --port 0` with the global `--json`, and reads `{"port","token","url"}` from the first stdout line. I checked this against `crates/vibe-cli/src/server/mod.rs` and with a probe of the installed `vibe` 0.4.0.
   - The token file `.vibe/server.token` is **not** used: another `vibe serve` on the same project would overwrite it.
2. **Stopping uses SIGINT, not SIGTERM.** The server only listens for Ctrl-C (`tokio::signal::ctrl_c`), and SIGTERM would skip cancelling the runs. On ⌘Q the `AppDelegate` sends SIGINT and waits up to 2 s; the server finishes its shutdown on its own.
3. **CI in its own workflow.** At first a `macos-app` job was appended to `ci.yml` behind `dorny/paths-filter` (GitHub has no job-level `paths` filter). At the lead's request it moved to `.github/workflows/macos-app.yml`, triggered on `pull_request` and on `push` to `main` with a native `paths: ["apps/macos/**", ".github/workflows/macos-app.yml"]` filter. Same steps: xcodegen, `swift test`, `xcodebuild … build CODE_SIGNING_ALLOWED=NO`, on `macos-latest`.
4. **Fixtures are hand-written from the Rust shapes.** I first tried to copy a real `.vibe/` log from another local project (ServersMonitor); the permission classifier refused, because the data comes from another project.
   - `events-legacy.jsonl` reproduces by hand the 0.4 shapes observed in that log, with invented ids and texts.
   - `events-0.5.jsonl` covers every type of `events.md`, plus one unknown type.
5. **Notifications come from board transitions, not events.** Only the selected task has a stream until the global one exists, while board polling covers every task of the project.
6. **Activity** shows the selected task's live feed, as the brief asks for now, plus the list of live tasks.
7. **`release.sh` builds a plain DMG.** It has no Finder layout and no `make-dmg-background.swift`. PLAN.md says the layout and Sparkle come with the first tagged release.
   - It checks `MARKETING_VERSION` against the requested version, writes to `apps/macos/VibeFactory/release/`, and signs with the entitlements, Developer ID and the notary profile `AppliMacVincentGithub`.
   - There are no nested frameworks to sign: VibeAPI is linked statically.
8. **Sandbox is off**, as the brief says; the reason is written in the README. Hardened Runtime is on.
   - A Finder-launched app does not see provider API keys exported only in shell startup files.
   - The README documents this and the workarounds: the config, `launchctl setenv`, or connecting to a terminal `vibe serve`.
9. **Smoke test side effect.** The smoke test serves the repository itself, and `vibe serve` creates `.vibe/tasks/` there. That directory is git-ignored, and I removed it after the run.
10. **Stream token in the header.** The brief said `stream?after=&token=`; the app sends the token in the `Authorization` header instead (the server checks the header first on `/stream`), so it stays out of URLs and logs. `?token=` is only needed by a browser's `EventSource`.
11. **Cancellation is not an error.** A cancelled `URLSession` request throws `URLError(.cancelled)`; `VibeClient` maps it to `CancellationError`, so debounced detail reloads and cancelled polling never raise an error alert. Regression test `testCancellingARequestIsACancellationNotATransportError` fails with `unexpected transport("annulé")` when the mapping is removed.
12. **Xcode scheme test action.** xcodegen accepted `testTargets: - package: VibeAPI/VibeAPITests`, so `xcodebuild test` also runs the package tests: 29 run (before the cancellation test was added), 1 skipped, TEST SUCCEEDED.
13. **Not verified: a manual session with the UI.** It was not possible from a non-interactive shell. What I did check:
    - the app builds;
    - the whole data layer is tested;
    - `ServerProcess` was exercised against the real `vibe`.

    The PLAN's "manual session against `vibe serve` on this repository" is still to do: open the app, open the repository, create a task, and run it with `--script` or a provider.

## Review fixes (round 1)

Scope unchanged: `apps/macos/` and `.github/workflows/macos-app.yml`; nothing committed.

**Majors**
1. No orphan server: the child's stdin is a `Pipe` the app keeps and never writes; the child runs with `--exit-on-stdin-eof`. **Requires vibe ≥ 0.5**: the smoke test against the installed 0.4.0 now fails with `unexpected argument '--exit-on-stdin-eof'` (clear message, no fallback). Stated in the README.
2. `ServerProcess.onExit(status, stderrTail)` fires when a started child dies without `stop()`. `ProjectSession` then turns to `.failed("vibe serve stopped (status N)…")`, and the window offers Retry. Test: `testOnExitReportsADeathAfterStart` uses a fake server that answers `/api/health`, then exits 3.
3. `TaskDetailViewModel.lines` is built in `receive()` and re-described only when the plan changes. `ActivityTab` reads `lines` only; the `LivePanel` subview alone reads `liveText`.

**Minors**
4. Line ids come from a monotone counter in the VM; trimming keeps ids aligned with the kept envelopes.
5. Settings → *Server environment variables*: names are stored in `UserDefaults`, values in the Keychain (`env:<NAME>`). They are passed as `ServerProcess(extraEnvironment:)`. The README no longer advises `config.toml`. Test: `testTheChildEnvironmentGetsTheAppKeys`.
6. SSE `id:` is buffered and committed at dispatch. Test: `testAnIdCountsOnlyWhenItsEventIsDispatched` (`"data: a\nid: 7\n"` then `finish()` leaves the id unchanged).
7. If `currentRun()` throws, the stream reconnects with `after=0` and keeps the cursor, so the `(run, seq)` check drops the replay. Tests: `testStreamReplaysFromTheStartWhenTheCurrentRunIsUnknown`, plus the existing same-run and new-run tests.
