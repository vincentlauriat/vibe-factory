Vibe Factory

Domain model

Every artefact the framework produces or exchanges is a plain Rust type in vibe-core, serialisable with serde. This page describes those types and shows how they look on disk. All types derive Serialize, Deserialize, Clone, Debug and PartialEq; most enums use #[serde(rename_all = "snake_case")], so TaskStatus::InProgress is written "in_progress".

Task ──1:1── Spec ──1:1── Plan ──1:n── PlanPhase ──1:n── Subtask
  │                                                        │
  └──1:n── QaReport (one per round) ──1:n── QaIssue        └── depends_on: [SubtaskId]

Run: RunId ──publishes──▶ Event (wrapped in Envelope) ──▶ EventBus
Agent session: SessionId, Message[] of ContentBlock, Usage

Identifiers

TaskId, SubtaskId, SessionId and RunId are generated by one macro in ids.rs: a newtype over a v4 uuid::Uuid, #[serde(transparent)], so each serialises as a bare string.

MethodPurpose
new() / default()fresh random id
parse(&str) / FromStrparse the canonical UUID form
short()first 8 characters, used in branch and directory names
Displayfull UUID

The ids are distinct types, so passing a TaskId where a SubtaskId is expected does not compile.

Phases always run in order; the subtasks of a phase may run concurrently when parallel is true. Plan offers subtasks() / subtasks_mut() (plan order), subtask(id), len(), is_empty() and is_complete() (every subtask done or skipped).

Plan::validate() rejects two kinds of broken plans with an ErrorKind::Config error:

  1. a depends_on entry naming a subtask that is not in the plan ("subtask <id> depends on unknown subtask <id>");
  2. a dependency cycle, found with Kahn’s algorithm: every subtask starts with an in-degree equal to its number of dependencies, subtasks at zero are dequeued, and each dequeue decrements the subtasks that depend on it. If fewer subtasks are dequeued than exist, the remainder forms a cycle ("plan contains a dependency cycle").

Dependencies may cross phase boundaries; validation looks at the whole plan.

issues_at_least(Severity::High) filters by severity; is_blocking() is true for any verdict other than approved; to_markdown() renders the human-readable report.

Messages

A conversation is a Vec<Message>; each Message has a role (user or assistant) and a list of ContentBlocks. There is no system role: the system prompt travels separately in CompletionRequest::system. Tool results are sent back in a user message.

ContentBlock (tag type)Fields
texttext
thinkingtext (only when the provider exposes reasoning)
tool_useid, name, input (JSON matching the tool schema)
tool_resulttool_use_id, content (text), is_error (default false)
 
{"role": "assistant", "content": [
  {"type": "text", "text": "Reading the router first."},
  {"type": "tool_use", "id": "toolu_01", "name": "read_file", "input": {"path": "src/routes.rs"}}
]}

Helpers: Message::user, Message::assistant, Message::tool_results, text() (joins text blocks), tool_uses(), has_tool_use(), and estimate_tokens(), a deliberately rough 4-characters-per-token estimate used for context budgeting without a tokenizer.

Usage counts input_tokens, output_tokens, cache_read_tokens and cache_write_tokens (the last two default to 0). It supports combined, += and total() (input plus output).

Phase

Phase lists the pipeline stages in canonical order: assess, spec, plan, build, qa, fix, merge (Phase::ALL). as_str() gives the stable lowercase name used in [phases.<name>] configuration and CLI flags; FromStr accepts it case-insensitively and returns a Config error otherwise. The enum does not impose an order at run time: a pipeline may skip spec or loop fix → qa.

Errors

Every crate returns vibe_core::Result<T> with a single Error { kind, message, retry_after, source }. ErrorKind drives behaviour rather than display: RateLimited, ServerError and Network are the only kinds for which is_retryable() is true; ContextTooLong ends an agent run with AgentStop::ContextWindow; Denied is what policy checks return. io::Error converts to Storage, serde_json::Error to InvalidRequest, toml::de::Error to Config.

JSON is the source of truth

Complexity assessments, specs, plans and QA reports are produced by agents as JSON, parsed into these types, and saved as JSON. Markdown (Spec::to_markdown, QaReport::to_markdown) is rendered from the typed value for humans and is never parsed back. There is therefore one source of truth per artefact, and a malformed model answer is caught at the boundary by serde instead of deep in the pipeline. The rationale is in ADR-006; the extraction and repair strategy is in Agent runtime.

The JSON documents the built-in prompts ask for are the agent-facing shapes, not the persisted ones: they omit fields only the framework knows. The planner, for example, returns subtasks without id, status or attempts and names dependencies by subtask title, and the QA reviewer returns a report without task_id or round. Assigning ids, resolving titles to SubtaskIds and filling task_id and round is the caller’s job before a value becomes a Plan or a QaReport and before Plan::validate() runs.
